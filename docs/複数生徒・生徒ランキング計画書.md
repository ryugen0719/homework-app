# 複数生徒・生徒ランキング機能 計画書

作成日：2026年11月21日  
対象：宿題ノート（先生・生徒の2種類のアカウントで使う学習記録アプリ）

## 0. レビュー要約

### 現計画の評価

目指す方向（先生が生徒を作成する、1分1ポイント、継続ボーナス、招待制の生徒ランキング）は一貫している。一方、実装に進む前に、アカウント切り替えと本人確認、ポイント計算の基準、招待グループの権限を具体化する必要がある。

### 先に解消する問題

1. **画面上の生徒選択とログイン主体が混ざっている。** 生徒画面から別の生徒へ切り替えられる設計では、選択だけで別人の記録を作成・閲覧できるように見える。先生の「担当生徒を切り替える」操作と、生徒の「自分としてログインする」操作を分ける。
2. **現行の共通生徒トークンでは個別権限を作れず、写真APIも生徒所有者を識別していない。** 先生用・生徒用それぞれ単一トークンの現状から、先生・生徒ごとの認証主体とAPI認可へ移行する必要がある。特に証拠写真の取得・アップロードAPIは、単なるログイン確認だけでなく、対象セッションの生徒所有者を確認しなければならない。
3. **ポイント集計の根拠がまだ曖昧。** 時間未入力、記録修正、同日複数記録、日付境界、継続ボーナス条件、週の締めを決め、画面上に計算内訳を出す。
4. **1分1点は時間を使える量の差を解消しない。** 実時間で競う指標として透明に示し、先生が作るグループや同じ条件のリーグを選べるようにする。年齢補正を隠れた係数で行わない。
5. **ランキングから記録内容が漏れない境界が必要。** グループにはポイントなどの集計値だけを返し、勉強内容、写真、先生のコメントはAPIでも返さない。

### 推奨する判断

- 生徒は自分のアカウントでログインし、自分の記録だけを見る。生徒用の画面に他人へ切り替える機能は置かない。
- 先生は担当する生徒を一覧から切り替えられる。共有端末で生徒が交代する場合はログアウト後、先生が作成した生徒アカウントを選んで本人用の暗証情報で入り直す。
- 先生1人あたりの生徒アカウントは初期上限5人。ランキンググループには複数の先生が管理する生徒も、参加承認後に加えられる。
- 週ポイントは「その週に保存された有効な学習分数の合計 + 継続ボーナス」。1分は1ポイント、分数の丸めなし。同点は同順位とする。
- ランキングは招待・参加承認制で、初期状態は非公開・不参加。ごほうび機能は対象外。

## 1. 目的

先生が複数の生徒アカウントを作成・管理し、学習記録を混同せず扱えるようにする。アカウントの切り替えを簡単にし、勉強時間を中心に、毎日取り組む習慣も少し評価するポイントランキングを提供する。ランキングには先生が招待・承認した生徒が参加でき、家族・友達といった関係区分は設けない。

## 2. 現状

- アカウント種別は先生と生徒の2種類。現在は先生1人・生徒1人を前提としたトークン認証で、生徒用トークンは1つ。
- Firestore の `days/{日付}` に全生徒分を保存している。ドキュメントIDに生徒IDが含まれないため、生徒別に移す必要がある。
- 日ごとの勉強内容、任意の学習時間・写真、先生のコメントを記録できる。
- 統計画面には学習時間、記録率、連続日数、育成型バッジが既にある。
- そのため、複数生徒対応では表示だけでなく、記録・写真・コメント・統計の全てに生徒IDを紐づける必要がある。

### 現行APIの移行対象

| API | 現在の役割認証 | 複数生徒化で必要な認可 |
|---|---|---|
| `/api/entries` | `teacher` / `student` の役割判定。先生の全件取得もある | 生徒は自分のIDだけ、先生は担当生徒だけ。ランキングの集計APIは別レスポンスにする |
| `/api/evidence/upload` | 生徒役割、日付、セッションIDを確認 | 認証主体が対象セッションの生徒本人かを確認 |
| `/api/evidence` | ログイン役割と写真パス・セッションの存在を確認 | 認証主体の担当・所属権限を確認。写真パスを知っているだけでは取得不可 |

現在は共通の生徒トークンが1つなので実利用上の生徒間境界がないが、個別アカウント化後に既存認可のまま残すと、他人の記録・写真へのアクセスにつながる。データ移行と同じリリースで全APIを生徒ID・担当先生IDに対応させる。

## 3. 設計方針

1. **まず個人の記録を正しく分ける。** どの画面・APIでも選択中の生徒IDを確認し、他の生徒の記録を誤って表示・更新しない。
2. **勉強時間をポイントの中心にする。** 継続ボーナスは嬉しい上乗せに留め、時間ポイントを逆転するほど大きくしない。
3. **参加グループを限定する。** 先生が管理する招待制の生徒グループを基本とし、家族・友達の区分や全体公開ランキングは作らない。
4. **競争は任意にする。** 参加は初期状態でオフ。先生が生徒に参加を説明し、生徒が参加を希望した場合に先生が有効化する。生徒はいつでも参加を止められ、その後のポイントはグループへ共有しない。
5. **入力のしやすさを優先する。** 学習記録からポイントを自動集計し、ポイント獲得のための別作業を増やさない。

## 4. ポイント設計（初期案）

### 基本ポイント

学習記録に入力した勉強時間を主得点にする。

- **時間ポイント：** 勉強1分につき1ポイント。30分なら30ポイント。
- **継続ボーナス：** その日に最初の学習記録をした時に加算。連続学習日数に応じて少し増やす。
- **ボーナス上限：** 1日あたりの継続ボーナスは最大5ポイント程度。時間ポイントが主役であり続けるようにする。
- **日次上限：** 初期案では設けない。誤入力・不自然な長時間記録は先生が確認・修正できるようにする。将来上限を設ける場合はルールとして事前告知し、週の途中では変更しない。
- **週次ランキング：** 月曜から日曜の日本時間で集計し、週ごとにリセット。月曜0時に次の週を開始し、前週分は月曜正午まで「集計中」、その後に確定する。累計ポイントは個人の記録として残す。同点は同順位で、時間など別指標を隠れたタイブレークに使わない。

継続ボーナスの初期案：その日に合計10分以上勉強した日を「継続日」とし、連続継続日数に応じて +1、+2、+3、+4、5日目以降は最大+5ポイントを加算する。同日複数記録でもボーナスは1回だけ。10分未満の記録にも時間ポイントは付けるが継続日には数えない。欠席日に減点せず、連続数が途切れた後も次の継続日から+1で再開する。週をまたいで連続日数を引き継ぐ。

30分の勉強では時間ポイント30点、5日以上の継続中なら合計35点となる。休んだ日の点数は減らず、ストリーク表示だけが区切られる。開始時に「継続ボーナスは任意の追加点で、休んでも減点されません」と説明する。10分条件とボーナス幅は試用で調整する。

### ボーナス候補と不正・偏り対策

- 最初の版は時間ポイントと継続ボーナスに絞り、教科ボーナス・写真提出ボーナス・記録件数ボーナスは付けない。学習内容の自己申告や写真の有無で差がつくのを避ける。
- 1日の時間ポイントは有効なセッションの分数の合計。同じ30分を3件に分けても、分数の合計が30分なら30点。通信再送で同じセッションIDが二重登録されないようにする。ただし異なる記録に同じ勉強時間を二重入力したことは自動判定できないため、ランキングは自己申告制と明示し、先生が修正できるようにする。
- 未来の日付、重複セッション、各記録の分数（現行上限1,440分）、日ごとの合計（最大1,440分）をサーバー側で検証する。異常な記録は自動で減点せず、先生の確認待ちとして扱う。
- 学習時間を空欄にした記録は時間ポイントも継続日も対象外とし、保存前にそのことを伝える。継続日条件はその日の合計10分以上。
- 週の途中にポイントルールを変えず、次週から適用する。
- ポイントは学習日の日付（日本時間）に属する週へ計上する。前週の学習を今週の順位へ付け替えない。週のランキングは月曜正午に確定し、それ以降の先生修正は個人記録を直すが、確定済み順位は変えず履歴に修正を残す。
- ランキングの時間は学習した実時間の自己記録であり、理解度や学力を示す得点ではないと画面に表示する。
- 集計中の週の記録を修正・削除した場合は、ランキングを再計算する。先生が修正した場合は旧値・新値・修正者・日時を記録する。週確定後の修正は学習履歴にだけ反映し、確定済み順位は変更しない。
- 学習時間は本人の自己申告値として扱い、ランキング参加のために写真提出や監視タイマーを必須にしない。先生は誤記録を修正できるが、修正理由を残す。

### 年齢差とランキンググループ

時間を主軸にすると、年齢・学年・宿題量による差は完全には消えない。対策は得点を複雑に補正するより、誰と競うかを選べるグループ設計とする。

- 招待制の生徒グループ内ランキングを基本にし、必要なら先生が学年や学習環境の近い生徒でグループを分ける。正確な年齢・生年月日はランキング目的で収集しない。
- 初期の1グループは最大5人にする。全員を同じグループにするか、近い条件の生徒ごとに分けるかを先生が決める。グループ定員を超える場合は新しいグループを作る。
- 学習時間の実数とポイントの両方を表示し、ボーナス由来の点数も内訳で確認できる。
- 年齢補正係数を得点に隠して適用しない。時間を競うランキングであることを明記し、先生が同じ条件の生徒を分けたグループも作れる。
- 競争に参加しない個人モードを用意し、順位を隠せる。

### 徒競走表示

- 人物キャラクターは使わず、色と表示名・任意アイコンによる横並びのシンプルなバーにする。
- 週のポイントを距離に換算し、勉強時間と継続ボーナスでバーが進む。各レーンに「今週 185 pt」「勉強 180分 + 継続 5 pt」と内訳を出す。分数とポイントの対応を常に示す。
- ランキングの主役は横棒レースにし、全レーンを同じスケールで表示する。最高点に合わせて横軸を自動調整し、0点でもバー・名前・0 ptを表示する。
- 順位は点数の右側にテキストで併記する。色だけに順位を担わせず、色覚差や小画面でも読めるようにする。
- 順位が変わった時だけ控えめなアニメーションを付け、動きを減らす設定も尊重する。
- 順位の強調を抑えた「今週の自分の記録」表示も選べる。

## 5. 招待制の生徒ランキンググループ

- 先生がグループを作成し、期限付き・一回限りの招待コードまたはリンクを発行する。参加できるのは先生が作成した生徒アカウントのみ。グループ作成先生は集計値だけを共有し、生徒の担当先生だけが詳しい学習記録を閲覧できる。
- 参加対象の生徒を管理する先生が、招待先グループと参加者を確認・承認する。アカウントの関係が家族か友達かは登録・表示しない。
- メールアドレスや電話番号による生徒検索、全体公開プロフィール、公開ランキングは設けない。
- グループに表示する名前とアイコンも先生が設定する。本名・学校名・年齢・学習内容・写真・先生コメントはランキングに出さない。
- グループを作成した先生がメンバー構成とグループを管理する。参加生徒の担当先生は自分が管理する生徒の参加承認・停止を行う。生徒本人もいつでも参加を止められ、その後のポイントをグループAPIに返さない。
- グループ画面の共有データは週ポイント、勉強時間の合計、連続日数などの集計値だけに限定する。
- 週次集計の開始曜日・タイムゾーンをグループで統一し、途中参加者は参加日以降を集計する。
- 招待コードの消費、5人定員の確認、メンバー追加はサーバー側の一つのトランザクションで処理し、同時参加による定員超過やコードの二重利用を防ぐ。

Duolingoを参考に、週間ポイントで短い競争期間を作る。公開プロフィール型ソーシャル機能は採用せず、先生が管理する小規模な招待制グループに限定する。

## 6. 生徒の切り替えと権限

- **生徒アカウントはすべて先生が作成する。** 生徒本人はアカウントを新規作成できない。
- 先生が管理画面用の名前、色、任意アイコンを設定する。生徒側から変更できない。ランキング上では管理名をそのまま出さず、グループごとに先生が設定する表示名を使う。生年月日・正確な年齢は初期プロフィールに含めない。
- 先生1人あたりの生徒数上限は初期値5人とする。追加・編集・停止・認証情報の再発行は先生画面から行う。ランキンググループには、異なる先生が作成した生徒も参加できる。
- 生徒は担当する先生が作成したアカウントで参加する。生徒本人が独自にアカウントを作る方式にはしない。
- プロフィール項目は先生が管理する名前、色、任意アイコン。グループ固有の表示名と参加設定はグループ単位で管理する。
- 生徒ログインは個人アカウントに固定し、自分以外の記録へ切り替えられない。共有端末では「生徒を切り替える」からセッションと画面内キャッシュを消去してアカウント選択へ戻る。先生が作成したアカウントを選び、本人用暗証情報で認証してから新しいセッションを開始する。アカウント選択は本人確認の代わりにならない。
- 先生画面には担当生徒の検索可能な切り替え一覧を置き、現在見ている生徒名を全ページに表示する。記録の追加・編集前にも対象生徒名を確認できる。
- 生徒本人の氏名・表示名などプロフィール項目は先生だけが設定・変更する。ログイン用の秘密情報は本人だけが使えるものにし、先生が再発行できる。
- 生徒ごとにアクセスできる記録をサーバーで認可する。URLや画面側の生徒ID切り替えだけでアクセス権を与えない。
- 生徒グループのランキング画面で他の生徒に見せる情報を絞る。初期表示は週ポイント、勉強時間合計、色・表示名とし、学習内容や写真、先生のコメントは共有しない。
- 先生は担当する生徒の記録を閲覧できる。ランキンググループの共有範囲は先生が設定する。
- 共有は招待制グループ単位で認可し、招待コードの有効期限、担当先生の参加承認、退出・ブロックを管理する。

### アカウントとグループのライフサイクル

- **停止**はログインと新規ポイント共有を止め、既存記録を保持する。**完全削除**は最終確認後に生徒記録、写真Blob、グループ表示名、参加中・確定済みグループスコアを削除する。画面では2つの操作と影響を明確に分ける。
- 生徒がグループ参加を停止した場合、所属・今週のスコアを直ちにグループAPIから除外する。先生が完全削除した場合、グループの確定スコアも削除し、順位を再表示する。
- 先生アカウントを停止・削除する場合、担当生徒の引き継ぎまたは削除、グループの管理権移譲・終了を先に確定し、孤立したデータを残さない。
- 退会・削除の履歴は必要最小限にし、氏名・学習内容・識別子を監査ログや集計APIに残さない。削除イベント自体を保持する場合は個人へ再結合できない形にする。

## 7. 認証・権限とデータ移行

### 認証方式

- 現行の `TEACHER_TOKEN` / `STUDENT_TOKEN` と `/t/[token]`・`/s/[token]` は先生1人・生徒全員共通の権限であり、複数生徒化後は使い続けない。
- 最初の先生アカウントは既存の先生アカウントを移行して作る。一般公開の先生登録画面は作らず、追加の先生アカウントは既存先生が招待・承認して作成する。ユーザー種別は先生と生徒の2種類のままとする。
- 先生と各生徒に個別の認証UIDを割り当てる。先生はログイン後、自分が作成した生徒だけを管理する。ランキング表示用の生徒IDは担当先生とグループ所属を確認した後にのみ扱う。
- 生徒にメールアドレスを要求しない初期ログインを推奨する。先生が生徒アカウントを作成してランダムなログインIDと期限付き一回コードを発行し、生徒が初回ログイン後に本人用の秘密情報を設定する。サーバーがID・コードを検証してFirebase Custom Tokenを発行し、クライアントがFirebaseでサインインした後、IDトークンをサーバーへ交換してセッションCookieを設定する方式を認証プロトタイプで確認する。
- 一回コードは高エントロピー・短期限・一度限りとし、保存時はハッシュ化する。短いPINを採用する場合はログイン試行をレート制限し、連続失敗時に一時停止する。パスワードやPINの平文は保存せず、先生にも表示しない。先生の再発行で旧セッションを失効させる。
- セッションはHttpOnly・Secure・SameSite Cookieとし、ログアウト・失効・期限切れを備える。書き込みAPIはCSRF対策（Origin検証等）も行う。認証情報や招待コードをURLクエリ・パスへ置かない。
- すべてのAPIで「認証済み主体」「ロール」「担当先生との関係」「グループ所属」をサーバー側で検証する。Firebase Admin SDKはFirestore Security Rulesを迂回するため、APIの認可を省略しない。

### 推奨データモデル

- `teachers/{teacherId}`：先生アカウントと管理設定。
- `students/{studentId}`：担当先生ID、認証UID、先生が設定した管理名、色、任意アイコン、状態。正確な生年月日や年齢は保存しない。
- `students/{studentId}/days/{date}`：学習セッション、日ごとの先生コメント。ポイント対象日はこの文書IDの日付で判定し、クライアント時刻だけに依存しない。
- `groups/{groupId}`：グループ名、作成先生、最大5人の定員、週次ルール、共有設定。
- `groups/{groupId}/members/{studentId}`：参加状態、所属先生、グループ内表示名、参加日、表示設定。
- `groups/{groupId}/invites/{inviteId}`：招待コードのハッシュ、有効期限、発行者、使用済み状態。コード原文は保存しない。
- `studentAuth/{authUid}`：初回コード・秘密情報の検証に必要なハッシュ等を保護されたサーバー専用データとして保存。通常の先生・生徒画面APIでは返さない。
- `groups/{groupId}/weeks/{weekId}`：集計状態（open / finalizing / final）、ルール版、確定時刻。
- `groups/{groupId}/weeks/{weekId}/scores/{studentId}`：週締め時の確定スコアスナップショット。時間合計と継続ボーナス内訳を持つが、学習内容・写真は複製しない。確定後は不変とする。
- `audit/{eventId}`：先生による学習時間修正、参加承認、アカウント停止などの主体・対象・日時・変更理由。学習内容本文や写真は複製しない。

週間集計の境界は日本時間・月曜開始で統一する。進行中の順位はサーバー側で日次記録から都度集計し、クライアントから送られた順位や合計を正として扱わない。月曜正午にサーバー側の週締め処理が前週の対象記録を計算し、グループ状態と確定スコアを一度だけ保存する。処理は再実行可能にし、失敗時は確定済みと表示せず再試行する。確定スコアにはポイントルール版と確定時刻を記録する。

### 既存データ移行

1. FirestoreとBlob参照のバックアップを取る。移行中に書き込みを止める時間を決める。
2. 既存の `days/{date}` を現在の生徒ID配下へ移す。既存記録を複数人へ推測で分配しない。
3. セッション数、学習時間、レビュー、写真参照を日付ごとに照合する。旧形式からの再移行・ロールバック手順を用意する。
4. 生徒別API・先生別APIへ画面を切り替え、旧形式の読み書きを停止する。
5. 既存の共通トークンを無効化し、先生・生徒それぞれの初回ログイン情報を発行する。

ランキング開始日は週の月曜0時（日本時間）に合わせる。既存記録は最初の生徒の過去統計として残すが、開始日前の記録からポイントや継続ボーナスを遡って付与しない。

写真の取得・アップロードAPIも、認証主体、対象生徒、日付、セッションIDの所属を毎回検証する。新しいBlobパスには生徒IDを含め、非公開Blobであることに加え、別生徒や別グループから写真を取得できないことを確認する。

## 8. 画面案

### 生徒画面

1. **ログイン後のヘッダー：** 先生が設定した生徒表示名。別生徒の記録へ切り替えるUIは表示しない。別アカウントへ移る操作は「生徒を切り替える」と明示し、現セッションを閉じて再認証する。
2. **今週のレース：** 対象週・自分の順位・合計ポイントを最初に表示。続けて競走バーと全員の点数を表示。
3. **点数の説明：** 「勉強時間 30分 = 30点」「継続ボーナス +3点」のように、合計が何からできているか常時確認できる。
4. **学習記録：** 分数を入力すると保存前に獲得ポイントを予告。未入力の場合は「ポイント対象外」と保存前に伝える。記録内容・写真はランキングメンバーに共有されないと明記する。
5. **順位以外の振り返り：** 今週と前週の自分の勉強時間、連続学習日数、先生コメントを見られる。学習時間は習熟度の評価ではないと分かる文言を添える。
6. **空・読込・エラー状態：** 新規参加、まだ記録がない週、読み込み中、通信失敗、参加停止を区別する。通信失敗時は入力を保持し、再試行できる。

### 先生画面

1. **生徒一覧：** 名前、今週の記録有無、未確認コメントを一覧化。主操作は「生徒を追加」と「生徒を見る」。
2. **生徒作成：** 先生が名前・表示名・色を設定し、アカウントを作成。初回アクセス用の一回限りコードを発行する。作成完了画面で生徒へ渡す方法を案内する。
3. **生徒詳細：** カレンダー、タイムライン、統計、写真、先生コメント。記録を修正した時はポイントへの影響と変更履歴を表示する。
4. **グループ：** 作成、招待コードの発行・失効、参加申請の承認、表示名、公開項目、参加停止、メンバー削除を管理。
5. **週の確認：** ポイント内訳、未確認の時間修正、同点を含む確定順位。学習内容と写真はグループ画面に出さない。

### 主要フロー

**先生が生徒を追加する：** 先生ログイン → 生徒追加 → 先生が名前・表示名を設定 → 初回コードを発行 → 生徒がコードで初回ログイン → 生徒用の秘密情報を設定。

**生徒が記録する：** 生徒ログイン → 今週のポイントとレースを確認 → 学習内容・分数を入力 → 保存前に「今回 +30点、継続 +2点」を確認 → 保存 → レースの進みと獲得内訳を見る。

**共有端末で生徒を交代する：** 生徒画面で「生徒を切り替える」→ セッションとメモリ上の記録・写真を破棄 → アカウント選択 → 個人用PIN/パスフレーズ → 新しい生徒のホーム画面。認証に失敗した場合は前のアカウントへ戻さず、ログイン画面に留める。

**先生が生徒をランキングに招待する：** グループ作成 → 招待コードを発行 → 相手の担当先生が参加する生徒を選択・承認 → 生徒へ共有項目と表示名を説明 → 生徒の希望を確認して参加有効化。

このフローで、先生は複数生徒を管理できる一方、生徒は他の生徒として操作できない。プロフィール名・ランキング表示名の変更権限は先生に限る。

## 9. 開発フェーズ

| フェーズ | 対応内容 | 完了条件 |
|---|---|---|
| 0. ルール確定 | 1分1点、継続ボーナス、グループ定員、共有項目を決める | 初期ルールを説明でき、週途中に変更しない運用が決まる |
| 1. 認証・複数生徒基盤 | 認証プロトタイプ、個別UIDとセッション、先生による生徒作成、全APIの個人認可、既存データ移行 | 生徒間で記録・写真・コメントが混ざらず、別生徒IDを指定しても閲覧・更新できない |
| 2. 切り替え・生徒別表示 | 先生用生徒一覧、個人ログイン・ログアウト切り替え、生徒別統計 | 先生は担当生徒を迷わず選べ、生徒は自分以外の記録にアクセスできない |
| 3. ポイントと生徒ランキング | 1分1点、継続ボーナス、週次集計、週締め処理、徒競走バー | 同一IDの再送で二重加算されず、内訳が説明でき、確定処理の再実行で結果が変わらない |
| 4. 生徒グループ | 担当先生が作成したアカウントへの招待、先生による参加確認、限定共有、参加停止 | 未承認アカウントが参加できず、集計APIから学習内容・写真を取得できない |
| 5. 試用・調整 | 4週間、操作負担・継続性・楽しさ・公平感・共有範囲を確認 | 問題を直し、先生・生徒が継続可否を判断 |

フェーズ1・2が終わるまではランキングを公開しない。ごほうび機能は今回の対象外とする。まず記録分離と認可を確実にする。

## 10. 試用時に見る指標

- 生徒を切り替えてから記録を保存するまでの操作数と時間。
- 間違った生徒に保存された件数（目標0件）。
- 初回コードからログイン完了までの成功率、ログアウト後に別生徒へ正しく切り替えられた割合。
- 生徒ごとの時間ポイントと継続ボーナスの割合、記録日数、参加率。
- 「年齢や宿題量の差で不公平」と感じた回数と理由。
- 競争が楽しかったか、プレッシャーになったか（簡単な3段階確認）。
- 生徒グループの招待・先生による承認・退出が分かりやすいか。
- 表示名や学習内容など、共有範囲について不安がなかったか。

ランキングの勝敗や参加率だけで成功を判断せず、記録しやすさと本人の納得感を重視する。

## 12. 推奨する初期リリース

最初の公開範囲は、**先生が作成する最大5人の生徒アカウント、簡単な切り替え、生徒別の記録と統計、勉強1分1点の週次ポイント、控えめな継続ボーナス、招待制の生徒ランキンググループ**までとする。参加者の関係による区分は設けず、先生と生徒の2種類のアカウントだけを扱う。ごほうび・罰ゲーム機能は実装しない。

## 13. 実装完了の受け入れ条件

- 先生は最大5人の生徒アカウントを作成・停止し、名前・管理名・グループ表示名を設定できる。生徒はアカウントや名前を作成・変更できない。
- 生徒Aのセッションで生徒BのID・日付を指定しても、Bの記録・写真を取得・変更できない。先生Aは担当していない先生Bの生徒の詳細記録を見られない。
- 他の先生が管理する生徒は、担当先生の承認前にはランキングに表示されず、参加後も集計値以外を他グループ参加者に返さない。
- 学習記録を1分・任意の複数セッションで保存した時、ランキングの時間ポイント合計は学習分数と常に一致する。分割・再送・再読み込みで二重加算されない。
- 集計中の週は記録追加・編集・削除・先生修正後にポイントと順位が再計算され、修正履歴が残る。確定週は後日の記録修正で確定スコアが変わらない。
- 継続日条件未満の記録、未入力時間、休んだ日、週またぎ、週開始・終了、同点、途中参加の表示と計算が仕様どおりである。
- 招待コードは期限・使用回数が制御され、再使用や期限切れで参加できない。退出後のデータアクセスも拒否される。
- 週締め処理を複数回実行しても同じ週スコア・同点順位が維持され、失敗時は未確定状態から安全に再試行できる。
- 完全削除後、削除対象の個人記録・写真・認証情報・グループスコアが取得できず、残る監査情報から個人を特定できない。
- ログアウト後は端末の戻る操作で前の生徒の画面・写真が再表示されず、別の生徒のセッションで入った記録は明示的に対象が分かる。
- 画面幅が狭くてもポイントの内訳・氏名・順位が読み取れ、色だけに依存せず、キーボード操作と読み上げに対応する。動きを減らす環境設定ではバーのアニメーションを止める。
